# Artisan Roaster Scope → Home Assistant: Setup Guide

Build: `__COMMIT__` · Release: <__RELEASE_PAGE_URL__>

This guide takes you from nothing to live roast data in Home Assistant. There are two parts:

| Part | Runs on | What it does |
|---|---|---|
| **artisan-ha-bridge** | The laptop running Artisan | Reads Artisan's WebLCDs telemetry and event actions, computes phase, RoR, development time and DTR, and serves them to Home Assistant on TCP 8765. |
| **Artisan Roaster Scope** integration | Home Assistant | Connects to the bridge and exposes sensors, binary sensors, an event entity, device triggers and bus events. |

Artisan itself is not modified.

```
Artisan ──WebLCDs :8080──▶ artisan-ha-bridge ──WS :8765 (LAN, token)──▶ Home Assistant
        ──WebSocket :8766─▶ (127.0.0.1 only)
```

## 1. Requirements

**Artisan laptop (Linux)**
- Artisan 3.x, run by a normal desktop user.
- Python 3.11 or newer with `venv` (Debian/Ubuntu: `sudo apt install python3 python3-venv`).
- systemd with user services (any mainstream desktop distribution).
- `curl` or `wget`.
- Reachable from Home Assistant on TCP 8765, on the same LAN. Zeroconf/mDNS discovery needs both on the same subnet; manual setup by IP works without it.

**Home Assistant**
- Home Assistant 2026.10 or newer.
- HACS, for the HACS install path (optional; a manual install is described too).

macOS and Windows hosts are supported by the bridge but not by the installer script; see
[Other operating systems](#other-operating-systems).

## 2. Install the bridge on the Artisan laptop

Run as the user who runs Artisan (not root):

```sh
curl -fsSL __RELEASE_BASE_URL__/install.sh | bash
```

Add `-s -- --open-firewall` to also open TCP 8765 in ufw or firewalld (asks for sudo):

```sh
curl -fsSL __RELEASE_BASE_URL__/install.sh | bash -s -- --open-firewall
```

The installer:

1. Checks for Python 3.11+ and `venv`.
2. Downloads `artisan-ha-bridge.tar.gz` from this release and installs the bundled wheel into a
   private virtualenv at `~/.local/share/artisan-ha-bridge/venv`.
3. Links the CLI to `~/.local/bin/artisan-ha-bridge`.
4. On first install, runs `artisan-ha-bridge init`, which writes
   `~/.config/artisan-ha-bridge/config.yaml` with a random bridge id and access token. Re-running
   the installer keeps the existing config, so Home Assistant keeps working after an upgrade.
5. Installs `~/.config/systemd/user/artisan-ha-bridge.service`, enables it (it starts at login,
   like Artisan) and restarts it.
6. Prints the token and the next steps.

**Offline install:** download `artisan-ha-bridge.tar.gz`, then:

```sh
tar -xzf artisan-ha-bridge.tar.gz
./artisan-ha-bridge/install.sh
```

**Installer options:** `--from FILE` (use a local tarball), `--no-service` (CLI only),
`--open-firewall`, `--uninstall`, `--purge` (with `--uninstall`, also delete the config).

**Get the token again at any time:**

```sh
artisan-ha-bridge show-token
```

**Firewall without the installer flag:**

```sh
sudo ufw allow 8765/tcp                                                   # ufw
sudo firewall-cmd --permanent --add-port=8765/tcp && sudo firewall-cmd --reload   # firewalld
```

The ingest port 8766 binds to 127.0.0.1 only and must not be opened.

### Bridge configuration

`~/.config/artisan-ha-bridge/config.yaml`:

```yaml
bridge_id: <uuid4, generated by init>
unit: C                      # C or F; must match Artisan's temperature mode
weblcds: {host: 127.0.0.1, port: 8080, path: /websocket}
ingest: {port: 8766}
ha: {bind: 0.0.0.0, port: 8765, token: <secret>, sample_interval_s: 1.0}
ror_window_s: 30
offline_after_s: 10
autosave_dir: null           # set to Artisan's autosave folder to enrich summaries from .alog files
log: {level: INFO}
```

After editing: `systemctl --user restart artisan-ha-bridge`.

Setting `autosave_dir` to the folder from Artisan's **File > Save > Autosave** settings
adds the roast title, beans and in/out weights to the roast summary once Artisan writes the
`.alog` file.

### Other operating systems

The bridge runs on macOS and Windows as well. Install it with `pipx install
artisan_ha_bridge-<version>-py3-none-any.whl[watch]` (the wheel is inside
`artisan-ha-bridge.tar.gz`), run `artisan-ha-bridge init`, then install the bundled service file:

- **macOS:** `org.artisan-ha-bridge.plist` → `~/Library/LaunchAgents/`, then
  `launchctl load ~/Library/LaunchAgents/org.artisan-ha-bridge.plist`.
- **Windows:** import `artisan-ha-bridge.xml` in Task Scheduler, then allow inbound TCP 8765:
  `netsh advfirewall firewall add rule name="artisan-ha-bridge" dir=in action=allow protocol=TCP localport=8765`.

The bridge README bundled in the tarball has the details.

## 3. Configure Artisan

The bridge gets **telemetry** (BT, ET, timer) from Artisan's WebLCDs server, and **events and
slider values** from Artisan event actions that send small JSON messages to the bridge.

1. **Config > Curves > UI tab:** enable **WebLCDs** on port **8080**. Tick **Alarm Popups** to
   forward Artisan alarms to Home Assistant.
2. **Config > Port > WebSocket tab:** host `127.0.0.1`, port `8766`, path `artisan`.
   If your roaster already uses Artisan's WebSocket device, skip this and use the **Call Program**
   column below instead.
3. **Config > Events > Buttons:** for each event slot, set Action = **WebSocket Command** with the
   command from the table. If a slot already drives the roaster, move the original action to a
   hidden custom button, add a second hidden button with the WebSocket Command, and set the slot
   to **Multiple Event** triggering both.
4. **Config > Events > Sliders:** for sliders not already bound to roaster control, set Action =
   **WebSocket Command** with the slider command.
5. Optional: **Config > Alarms** with a **Pop Up** action. These reach Home Assistant as `alert`
   events.
6. **Help > Save Settings.**

The bridge prints this table for your actual configuration with `artisan-ha-bridge print-actions`,
and with absolute paths for Call Program with `artisan-ha-bridge print-actions --fallback`.

| Slot | WebSocket Command | Call Program fallback |
|---|---|---|
| ON | `send(dict(k='ev',e='on',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev on {BT} {ET} {t}` |
| START | `send(dict(k='ev',e='start',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev start {BT} {ET} {t}` |
| CHARGE | `send(dict(k='ev',e='charge',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev charge {BT} {ET} {t}` |
| DRY END | `send(dict(k='ev',e='dry',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev dry {BT} {ET} {t}` |
| FC START | `send(dict(k='ev',e='fcs',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev fcs {BT} {ET} {t}` |
| FC END | `send(dict(k='ev',e='fce',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev fce {BT} {ET} {t}` |
| SC START | `send(dict(k='ev',e='scs',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev scs {BT} {ET} {t}` |
| SC END | `send(dict(k='ev',e='sce',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev sce {BT} {ET} {t}` |
| DROP | `send(dict(k='ev',e='drop',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev drop {BT} {ET} {t}` |
| COOL END | `send(dict(k='ev',e='cool',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev cool {BT} {ET} {t}` |
| OFF | `send(dict(k='ev',e='off',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev off {BT} {ET} {t}` |
| RESET | `send(dict(k='ev',e='reset',bt={BT},et={ET},tm={t}))` | `artisan-ha-bridge emit ev reset {BT} {ET} {t}` |
| Heat slider | `send(dict(k='ctl',ch='heat',v={}))` | `artisan-ha-bridge emit ctl heat {}` |
| Fan slider | `send(dict(k='ctl',ch='fan',v={}))` | `artisan-ha-bridge emit ctl fan {}` |

Notes:

- Use the commands exactly as written: `dict(...)` rather than `{...}`, and no `_` or `$`
  characters, because Artisan rewrites braces, underscores and dollar signs before sending.
- Other slider channels work the same way: any lowercase name of up to 16 letters or digits, for
  example `ch='drum'`. Each one becomes a sensor in Home Assistant.
- Artisan's WebSocket client starts on the first command, so the very first event after starting
  Artisan can be lost. The bridge also infers state from WebLCDs, so this is harmless.
- **Simulator mode** suppresses WebSocket Command actions. To test with the simulator, use the
  Call Program column.
- Call Program needs the full path when `~/.local/bin` is not on Artisan's PATH; use
  `print-actions --fallback`.

## 4. Install the Home Assistant integration

### Option A: HACS (custom repository)

HACS only installs from GitHub repositories. This project is developed on Forgejo and mirrored
to GitHub at **__GITHUB_REPO_URL__**.

1. In Home Assistant open **HACS**, then the **⋮** menu > **Custom repositories**.
2. Repository: `__GITHUB_REPO_URL__`, Type: **Integration**, then **Add**.
3. Search HACS for **Artisan Roaster Scope**, open it and click **Download**.
4. Restart Home Assistant (**Settings > System > ⋮ > Restart Home Assistant**).

Every build publishes a GitHub release with version `<base>.<build>` (for example `0.1.0.42`),
so HACS offers an update whenever a new build lands.

### Option B: Manual

1. Download `artisan-integration.zip` from the release: `__RELEASE_BASE_URL__/artisan-integration.zip`.
2. Unzip it into your Home Assistant config directory so the files end up in
   `<config>/custom_components/artisan/` (the zip contains `custom_components/artisan/`).
3. Restart Home Assistant.

## 5. Add the bridge in Home Assistant

With the bridge running:

- **Discovered:** **Settings > Devices & services** shows *Discovered: Artisan Roaster Scope*.
  Click **Add**, paste the token (`artisan-ha-bridge show-token` on the laptop) and submit.
- **Manual:** **Settings > Devices & services > Add integration > Artisan Roaster Scope**. Enter
  the laptop's IP address or hostname, port `8765` and the token.

The flow connects to the bridge and waits for its greeting before saving. Errors:

| Error | Meaning |
|---|---|
| Failed to connect | Wrong host/port, bridge not running, or TCP 8765 blocked by the laptop's firewall. |
| Invalid authentication | The token does not match `config.yaml`. |

If the token changes later (`artisan-ha-bridge init --force`), Home Assistant raises a
re-authentication notification asking for the new one.

**Options** (**Configure** on the integration):

- **Sample interval** (1–10 s): how often fast-changing sensors (temperatures, RoR, times) are
  written to Home Assistant. Raise it to shrink the recorder database.
- **RoR precision** (0–2 decimals).

## 6. Verify

On the laptop:

```sh
artisan-ha-bridge doctor                       # checks WebLCDs, ports, HA client, config
systemctl --user status artisan-ha-bridge
journalctl --user -u artisan-ha-bridge -f      # live log
```

`doctor` exits non-zero if any check fails. With Artisan closed the WebLCDs check fails; that
is expected.

In Home Assistant, the **Artisan (<hostname>)** device should show *Bridge connected: on*. Start
Artisan, turn on monitoring (ON) and the temperatures appear. CHARGE switches *Phase* to `drying`.

## 7. Upgrade and uninstall

**Upgrade the bridge:** run the install command again. Config and token are kept, and the service
is restarted.

**Upgrade the integration:** HACS shows an update; or replace `custom_components/artisan` from
the newest `artisan-integration.zip`. Restart Home Assistant.

**Uninstall the bridge:**

```sh
curl -fsSL __RELEASE_BASE_URL__/install.sh | bash -s -- --uninstall           # keeps config
curl -fsSL __RELEASE_BASE_URL__/install.sh | bash -s -- --uninstall --purge   # also deletes config
```

## 8. Troubleshooting

| Symptom | Check |
|---|---|
| *Bridge connected* is off | `systemctl --user status artisan-ha-bridge`; firewall on TCP 8765; the IP in the integration still matches the laptop (give it a DHCP reservation). |
| Connected, but *Artisan running* is off | WebLCDs is disabled or on a port other than `weblcds.port`; Artisan is not monitoring. |
| Temperatures update but no events | WebSocket port settings in Artisan (step 3.2), or the slot actions. Simulator mode needs the Call Program variant. Watch `journalctl --user -u artisan-ha-bridge -f` while clicking CHARGE. |
| Warnings about unknown events in the log | A typo in an event action; compare it with `print-actions`. |
| Bridge stops when you log out | Expected: it is a user service, like Artisan. To keep it running without a login: `sudo loginctl enable-linger $USER`. |
| Not discovered automatically | mDNS blocked between subnets/VLANs. Add the integration manually by IP. |
| Wrong unit | Set `unit:` in `config.yaml` to match Artisan's C/F mode and restart the bridge. |

Download diagnostics from the integration (**⋮ > Download diagnostics**) when reporting a problem;
the token is redacted.
